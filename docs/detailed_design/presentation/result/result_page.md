# 成績表画面 振る舞い仕様書

## 1. 機能概要

保存したテストの成績を、新しい順に一覧で表示する画面（`/results`）。ボトムナビゲーションバーの「成績」で開き、開くたびに読み直す。

対象の概要設計書は `docs/high_level_design/presentation/result/high_result_page.md`（根拠欄の `概要 §<見出し>`）。
成績の読み取りの結果は `docs/detailed_design/online_offline/flashcard_result_repository.md`（FRS-R）で定める。

ログイン中のユーザーは id が `u1` のユーザーとする。
フォルダ「F」（id `F`）と「G」（id `G`）があるものとする。
成績 R1 はフォルダ `F`・正解数 9・出題数 10・日時が端末の時刻で 2026-11-16 09:05、成績 R2 はフォルダ `G`・正解数 5・出題数 10・日時が端末の時刻で 2026-11-15 20:30 とする（R1 のほうが新しい。`getFlashcardResults` は日時の新しい順に返す）。

## 2. データ定義

### 2.1 FlashcardResult

| 項目 | 型 | 説明 |
|------|----|------|
| id | String | 成績の id |
| folderId | String | テストしたフォルダの id |
| totalCount | int | 出題数 |
| correctCount | int | 正解数 |
| date | DateTime | テストの日時 |
| updatedAt | DateTime | 更新日時 |
| correctRate | double | 正答率（correctCount ÷ totalCount。totalCount が 0 なら 0） |

### 2.2 ResultViewModel の状態

| 項目 | 型 | 説明 |
|------|----|------|
| （状態そのもの） | AsyncValue<List<FlashcardResult>> | 成績の一覧 |
| フォルダ名の対応（`folderNamesProvider`） | AsyncValue<Map<String, String>> | フォルダの id → フォルダ名。読み込みに失敗したら空 |

### 2.3 入力ルール

該当なし。

## 7. 対象外

- **`NotFoundFailure` / `NetworkFailure` / `AuthFailure`**: 成績・フォルダの読み取りは端末内のデータベースだけを使い、リモートと通信しない。一覧の取得で対象の不在も起きない（FRS 7章・FLD 7章）
- **成績の個別の削除・リセット**: 提供しない（`requirements.md` §6-4、概要 §目的）
- **削除したフォルダの成績**: フォルダの削除で成績も削除される（FLD-X）ため、画面では扱わない。フォルダ名が見つからない成績の表示は RST-D07 で定める
- **他のユーザーの成績を表示しないこと（原則-9）**: Repository の契約（FRS-R02）で検証する。画面では userId `u1` で呼ぶこと（RST-V02）だけを確かめる
- **円グラフ・正答率の色**: Widget テストで観測しないため、項目を作らない（区切りはテスト結果画面の FCM-G と同じ）
- **AppBar のタイトルの中央寄せ・0件のときのアイコン**: Widget テストで位置・アイコンの絵柄を観測しないため、項目を作らない
- **日時の時差の変換**: 端末のタイムゾーンを固定できないため、「端末の時刻で」の前提で書いた RST-D01 だけで確かめる
- **ボトムナビゲーションバー**: SHL で定める
