# アカウント情報画面 振る舞い仕様書

## 1. 機能概要

ログイン中のアカウントのメールアドレスを表示し、コピーできるようにする。メールアドレスとパスワードで登録したユーザーには、パスワードの変更方法（ログイン画面の「パスワードを忘れた方」で変更する手順）をダイアログで案内する。
設定画面の「アカウント情報」から開く（`/account`。ボトムナビゲーションバーは表示しない）。

## 2. データ定義

### 2.1 表示に使うユーザー情報（AppUser）

| 項目 | 型 | 説明 |
|------|----|------|
| email | String | ログイン中のアカウントのメールアドレス。Google で登録したユーザーは Google アカウントのメールアドレス |
| hasPassword | bool | メールアドレスとパスワードでログインできるか。true のユーザーにだけ「パスワード変更」を表示する |

### 2.2 入力ルール

該当なし（入力欄が無い）。

---

## 3. 画面仕様（AccountPage）

条件は「前提データ＋操作」、期待される動作は観測点で書く。
「メール登録のユーザー」は `AppUser.email` が「taro@example.com」、`hasPassword` が true のログイン中のユーザー、「Google のユーザー」は `email` が「taro@gmail.com」、`hasPassword` が false のログイン中のユーザーを指す。
「パスワードの変更ダイアログの本文」は、「パスワードは、ログイン画面から変更できます。」・空行・「1. ログアウトする」・「2. ログイン画面の「パスワードを忘れた方」を押す」・「3. このアカウントのメールアドレスを入力して送信する」・「4. 届いたメールのリンクから、新しいパスワードを設定する」を、この順に改行でつないだ1つの文字列を指す。

## 7. 対象外

- **ログインしていない状態でこの画面を開くこと**: ログインしていなければ、画面の移動の前にログイン画面（`/login`）に移される（ルーターの共通のリダイレクトで、この画面固有の振る舞いではない。リダイレクトの仕様書はまだ無い）ため、この画面は表示されない
- **アプリの中でパスワードを変更しないこと**: 変更の処理そのものが無く、観測する対象が無い。ダイアログに入力欄や「変更」のボタンが無いことは ACI-P01（「閉じる」ボタンだけ）で確かめる
- **メールアドレスが空のユーザー**: メールアドレスとパスワード・Google のどちらで登録してもメールアドレスがあり、空のユーザーは存在しない。ログインの方法（Apple でサインインなど）を追加するときに見直す（ユーザー決定 2026-11-03。ACI-Q01）
- **この画面を表示している間に、他の端末での退会が見つかったとき**: お知らせダイアログはアプリ全体の仕組みで画面ごとに動作が変わらないため、設定画面の仕様書の ACD-W で代表する（ユーザー決定 2026-11-03。ACI-Q02）
- **設定画面を経由せずにこの画面が表示されること**: アプリを起動し直すとスプラッシュ画面（`/`）から始まり、この画面は設定画面の「アカウント情報」からしか開けないため、戻る先は常に設定画面になる
- **`hasPassword` の判定**（どのユーザーが true になるか）: ログイン情報を作る `AuthRepository` の責務で、この画面はその値をそのまま使う
- **コピーの失敗**: クリップボードへの書き込みは失敗の結果を返さず、観測できる失敗が無い
- **コピーと「パスワード変更」の Failure（Unknown / NotFound / Network / Auth）**: どちらの操作も Repository を呼ばず、通信もしないため発生しない
- **「パスワード変更」の二重タップ**: 1回目のタップでダイアログが画面の上に重なり、「パスワード変更」を続けてタップできない（2回目のタップはダイアログの外側のタップになる。ACI-P03）。1回目のタップでダイアログの表示が始まってから2回目が届く前提
- **コピーのアイコン・「パスワード変更」のツールチップや読み上げの文言**: 概要設計書に定めが無い
- **パスワードの変更ダイアログの本文が長いときの表示**: 本文は固定の文言で、長さが変わらない

## 8. 要確認事項

仕様を決めてから「確定」に変更する。決まった行は削除せず「決定」列に記録する。

| ID | 論点 | 案 | 推奨 | 決定 |
|----|------|----|------|------|
| ACI-Q01 | ログイン中のユーザーのメールアドレスが空（`AppUser.email` が空文字）のときの表示とコピー | A: メールアドレスの無いユーザーは存在しない（メールアドレスとパスワード・Google のどちらで登録してもメールアドレスがある）として 7章に書く ／ B: 「メールアドレス」の行ごと表示しない ／ C: 「未登録」と表示し、コピーのアイコンを出さない | A（今のログイン方法では空にならず、B・C は使われない表示を作ることになる。Apple でサインインなどを追加するときに見直す） | 決定: 案A（2026-11-03） |
| ACI-Q02 | アカウント情報画面を表示している間に、他の端末での退会が見つかったとき | A: 設定画面の仕様書の ACD-W（どの画面でも、今の画面の上にお知らせダイアログを出す）で代表し、この画面では ID を作らない（7章） ／ B: この画面の上にお知らせダイアログが出て、OK でログイン画面に移ることを ID にする | A（お知らせダイアログはアプリ全体の仕組みで、画面ごとに動作が変わらない） | 決定: 案A（2026-11-03） |
