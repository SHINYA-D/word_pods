# 新規登録画面（画面構成・入力のチェック） 振る舞い仕様書

## 1. 機能概要

メールアドレスとパスワードでアカウントを作る画面（`/sign-up`）。ログイン画面の「新規登録」から開く。

対象の概要設計書は `docs/high_level_design/presentation/auth/sign_up/high_sign_up_page.md`（根拠欄の `概要 §<見出し>`）。
この画面の振る舞いの多くは、次の仕様書ですでに定めている。この仕様書は、そこで定めていない**画面構成と入力のチェック**だけを扱う。

| 内容 | 仕様書 |
|-----|-------|
| 規約への同意（チェックボックス・閲覧・「アカウント作成」を押せる条件）、アカウント作成の失敗（`AuthFailure`・`NetworkFailure`・`UnknownFailure`）、二重タップ、メールアドレスが空 | `docs/detailed_design/legal_consent/legal_consent.md`（LGL-S・LGL-T） |
| 確認メールの送信、送信完了ダイアログ、ダイアログを閉じた後の移動 | `docs/detailed_design/email_verification/email_verification.md`（EMV-A） |
| 新規登録後の初回の同期 | `docs/detailed_design/online_offline/online_offline.md`（SYN-L07〜L09） |

条件の「同意済み」は、規約の情報の読み取りが終わり、「利用規約に同意する」「プライバシーポリシーに同意する」の両方をチェックした状態を指す（LGL-S04）。

## 2. データ定義

### 2.1 入力欄

| 項目 | 型 | 説明 |
|------|----|------|
| メールアドレス | String | 前後の空白を除いてアカウント作成に使う |
| パスワード（6文字以上） | String | 入力したままアカウント作成に使う |
| パスワード（確認） | String | 確認のためだけに使う。アカウント作成には渡さない |

### 2.2 入力ルール

| ID | ルール | 守る層 | 境界値（有効 ／ 無効） | 根拠 | 確定度 |
|----|--------|--------|------------------------|------|--------|

| SGU-N02 | パスワードは6文字以上（上限は確かめない。文字種は問わない） | 画面。ViewModel 以下には5文字以下のパスワードは渡されない前提（テスト対象外） | 有効: `abcdef`（6文字） ／ `あいうえおか`（全角6文字） ／ `      `（半角空白6文字） ／ `　　　　　　`（全角空白6文字） 無効: `abcde`（5文字） ／ `a`（1文字） | 概要 §入力のチェック | 確定 |

## 7. 対象外

- **規約への同意・アカウント作成の処理・確認メール**: LGL・EMV で定める（1章の表）
- **`NotFoundFailure` / `RecentLoginRequiredFailure` / `TooManyRequestsFailure`（画面）**: `AuthRepository.signUpWithEmail` はこれらを返さないため、画面の行を作らない。ViewModel の文言の対応は SGU-V01〜V03 で定める
- **メールアドレスの形式・パスワードの上限**: 画面では確かめない（概要 §入力のチェック）。Firebase Authentication が `UnknownFailure` を返し、その表示は LGL-S26 で定める
- **通信エラーダイアログと強制ログアウト（原則-11）**: ログイン前の画面なので当てはめない
- **入力のチェックの文言の位置（入力欄の下）・赤字**: Widget テストで位置と色を観測しないため、文言が表示されること（SGU-A02〜A06）だけを確かめる
- **キーボードを表示しているときのスクロール**: Widget テストでキーボードの表示を再現しないため、小さい端末でスクロールできること（LGL-S22）で確かめる
