# スプラッシュ画面 振る舞い仕様書

## 1. 機能概要

アプリの起動時に最初に表示する画面（`/`）。ロゴを最低2秒表示し、ログイン状態・退会処理の記録・強制ログアウトの記録の確認が終わってから、ログイン画面（`/login`）かホーム画面（`/home`）へ移動する。

対象の概要設計書は `docs/high_level_design/presentation/auth/splash/high_splash_page.md`（根拠欄の `概要 §<見出し>`）。
退会処理の記録・強制ログアウトの記録の中身と、それによる表示（再開ダイアログ・お知らせダイアログ）は `docs/detailed_design/presentation/settings/settings_page.md`（ACD）で、メールアドレスが未確認のユーザーの振り分けは `docs/detailed_design/email_verification/email_verification.md`（EMV-G）で定める。

条件の「確認がそろった」は、次の3つがすべて終わった状態を指す: ログイン状態の読み込み、退会処理の記録の確認、強制ログアウトの記録の読み込み。
特に書かない限り、ユーザーはメールアドレスの確認済みとする。

## 2. データ定義

### 2.1 移動の判定に使う値

| 項目 | 型 | 説明 |
|------|----|------|
| ログイン状態 | 読み込み中 ／ ユーザー ／ 未ログイン（null） ／ 失敗 | Firebase Authentication のログイン状態 |
| 退会処理の記録の確認 | 確認中 ／ 確認済み | `AccountDeletionPhase.checking` の間は確認中 |
| 強制ログアウトの記録 | 読み込み中 ／ 読み込み済み（uid または null） | 他の端末での退会で強制ログアウトした uid |

### 2.2 入力ルール

該当なし（ユーザーが入力する項目はない）。

## 7. 対象外

- 退会処理の再開ダイアログ・アカウント削除のお知らせダイアログの表示（ACD で定める）
- 強制ログアウトの記録の読み込みそのもの・退会済みの確認（ACD で定める）
- 移動後のルーターの振り分け（未確認ユーザーの `/verify-email` への移動。EMV-G で定める。SPL-T13 は起動からの結合の確認だけ）
- Failure 4種類: この画面は Repository の Failure を直接受け取らないため、行を作らない
- 退会処理の記録の確認が失敗したときの扱い: ACD（途中で止まった場合）で定める
- 2〜4 の確認を並行して進めること: 待つ順番は画面から観測できないため、どれか1つが終わらない間は移動しないこと（SPL-T04, T09, T11, T17, T18）で確かめる
- 戻る操作（スプラッシュ画面の表示中）: 概要設計書に定めがなく、OS の既定の動作（アプリを閉じる）に任せる
