# 利用規約・プライバシーポリシーへの同意 振る舞い仕様書

## 1. 機能概要

ログイン中のユーザーについて、Firestore の `app_config/legal` の現行の版数と `accounts/{uid}.consents` の同意済みの版数を文書ごとに比べ、同意が必要なら今の画面の上に閉じられない「同意ダイアログ」を表示する。
判定は、ログインしたとき・ログイン済みでの起動時・フォアグラウンドに戻ったとき（resumed）に、裏で行う。
同意ダイアログのリンクと、設定画面の「このアプリについて」の項目から、WEB で公開している規約のページを全画面の WebView（「閲覧画面」）で読める。同意ダイアログの「ログアウト」でログアウトもできる。表示しているチェックボックスをすべてチェックして「同意する」を押すと、Cloud Functions の関数 `acceptLegal` に同意を送信する。
判定は、ログイン直後なら初回の同期が終わってから行い、オフラインからオンラインに戻ったときにも行う。`app_config/legal` が無い（または項目が欠けている）ときは、既定値を現行の版数・URL として使い、同意を素通りさせない。
新規登録は、新規登録画面で両方の文書に同意しないとできない。アカウントができたら、画面に表示した版数で同意を自動で送信する。
特定の画面に属さず、どの画面の上にも表示されるため、画面ではなく機能として仕様を定める。

## 2. データ定義

### 2.1 現行の規約の情報（LegalConfig。Firestore `app_config/legal`）

| 項目 | 型 | 説明 |
|------|----|------|
| termsVersion | String | 利用規約の現行の版数（改定日 `YYYY-MM-DD`） |
| privacyVersion | String | プライバシーポリシーの現行の版数（改定日 `YYYY-MM-DD`） |
| termsUrl | String | 利用規約の WEB ページの URL |
| privacyUrl | String | プライバシーポリシーの WEB ページの URL |

4項目のどれかが無い・文字列でない・空文字や空白だけの場合は、「現行の版数が無い」として扱う（LGL-R02〜R07, R24, R29〜R33, R41〜R45）。

「既定値」（`LegalConfig` の既定値。アプリと関数 `acceptLegal` の両方に同じ値で持つ）は次のとおり。「現行の版数が無い」ときは、判定・新規登録画面・設定画面で既定値を使う。

| 項目 | 既定値 |
|------|-------|
| termsVersion | `2026-10-12` |
| privacyVersion | `2026-10-12` |
| termsUrl | `https://word-pods-web.web.app/terms` |
| privacyUrl | `https://word-pods-web.web.app/privacy` |

### 2.2 入力ルール

該当なし（文字の入力欄が無い）。

### 2.3 同意済みの版数（LegalConsents。Firestore `accounts/{uid}.consents`）

| 項目 | 型 | 説明 |
|------|----|------|
| termsVersion | String? | 同意済みの利用規約の版数（`consents.terms.version`）。記録が無い・文字列でなければ null |
| privacyVersion | String? | 同意済みのプライバシーポリシーの版数（`consents.privacy.version`）。記録が無い・文字列でなければ null |

### 2.4 同意が必要かの判定結果（LegalConsentRequirement）

| 項目 | 型 | 説明 |
|------|----|------|
| termsRequired | bool | 利用規約への同意が必要か |
| privacyRequired | bool | プライバシーポリシーへの同意が必要か |
| config | LegalConfig | 判定に使った現行の規約の情報（送信する版数と、閲覧画面の URL に使う） |

### 2.5 同意の送信の結果（LegalAcceptResult）

| 値 | 意味 |
|----|------|
| accepted | 同意が記録された |
| outdated | 送った版数が現行の版数と違ったため、記録されなかった |

## 3. 画面仕様（LegalDocumentPage：同意ダイアログ・閲覧画面・設定画面の項目。Widget テストは閲覧画面のテストにまとめる）

用語の定義:

- 「同意ダイアログ」は、タイトル「同意のお願い」、本文「WordPods を利用するには、次の内容への同意が必要です。リンクから内容を確認し、チェックを入れてください。」、同意が必要な文書の行、「同意する」ボタン、「ログアウト」ボタンからなるダイアログを指す
- 「利用規約の行」は、リンク「利用規約を読む」とチェックボックス「利用規約に同意する」を指す
- 「プライバシーポリシーの行」は、リンク「プライバシーポリシーを読む」とチェックボックス「プライバシーポリシーに同意する」を指す
- 「閲覧画面」は、同意ダイアログのリンクから開く、全画面の WebView の画面を指す
- 「現行の版数」は `app_config/legal` の値を指す。特に書かない限り、`termsVersion` は `2026-01-01`、`privacyVersion` は `2026-01-01`、`termsUrl` は `https://example.com/terms`、`privacyUrl` は `https://example.com/privacy` とする
- 「未同意」は、`accounts/{uid}` に `consents` が無い状態を指す
- 「`app_config/legal` が無い」は、現行の規約の情報の読み取りが `NotFoundFailure` を返すことを指す
- 「初回の同期」は、新規登録・ログインの処理と、その直後に行う同期を指す（`authSyncInProgressProvider` が true の間。新規登録では同意の送信を含む）。同期が失敗しても、`authSyncInProgressProvider` が false に戻った時点で終わったものとする
- 「判定」は `CheckLegalConsentUseCase`（6章）を指す。「送信」は `LegalRepository.accept` を指す
- 「退会済みの記録」「退会処理の記録」「強制ログアウトの記録」「お知らせダイアログ」「再開ダイアログ（「退会処理が完了していません」）」は、設定画面（退会）の仕様書（ACD）の定義に従う

特に書かない限り、オンラインで、ログイン中の uid は `A`、退会処理の記録・退会済みの記録・強制ログアウトの記録は無いものとする。

## 4. 状態管理仕様（LegalConsentViewModel）

State の項目:

- `phase`: `idle`（待機）／ `checking`（判定中）／ `required`（同意ダイアログを表示している）／ `sending`（送信中）／ `signingOut`（同意ダイアログの「ログアウト」でログアウトしている）／ `networkError`（「通信エラー」ダイアログを表示している）
- `termsRequired` / `privacyRequired`: その文書の行を表示するか
- `termsChecked` / `privacyChecked`: その文書のチェックボックスがチェックされているか
- `config`: 判定に使った `LegalConfig`（送信する版数と閲覧画面の URL）。判定する前は null
- `message`: `null` ／ `sendFailed`（「同意を送信できませんでした。もう一度お試しください。」）／ `outdated`（「内容が更新されました。もう一度ご確認のうえ、同意してください。」）／ `signOutFailed`（「ログアウトできませんでした。もう一度お試しください。」）

メソッド: `check`（判定）／ `setTermsChecked` / `setPrivacyChecked`（チェックの切り替え）／ `accept`（送信）／ `signOut`（同意ダイアログの「ログアウト」）／ `acknowledgeNetworkError`（「通信エラー」ダイアログの OK）。
ログイン中の uid が null 以外の値に変わると `check` を行う。ただし初回の同期の間（`authSyncInProgressProvider` が true の間）は判定せず、同期が終わった（false に変わった）ときに `check` を行う。ログイン中の uid が null になると、State を初期値（`phase` が `idle`、4つの真偽値がすべて false、`config` と `message` が null）に戻す。
特に書かない限り、オンラインで、ログイン中の uid は `A`、現行の版数は 3章冒頭の値、退会処理の記録・退会済みの記録・強制ログアウトの記録は無く、他の端末での退会の `phase` は `idle` とする。

## 7. 対象外

- **関数 `acceptLegal` の中の動作**（版数の確認・`accounts/{uid}.consents` と `consent_logs/{uid}/logs` の書き込み・サーバー時刻・`merge`・何度呼んでも最新の同意が同じになること）: 関数の中の動作のため、Cloud Functions 側で Firebase Emulator を使って検証する（概要 §テスト）。概要 §目的の「いつ・どの版に同意したかを記録する」もこの範囲
- **Firestore のルール**（`consent_logs` をクライアントが読み書きできない・`app_config` を誰でも読める）: `@firebase/rules-unit-testing` と Firebase Emulator で検証する（概要 §テスト）
- **退会で同意の履歴が残ること**: 関数 `deleteAccount` は `users/{uid}` と `accounts/{uid}` だけを削除し、変更しない。Cloud Functions 側のテスト（`functions/test/delete_account.test.ts`）の範囲
- **現行の規約の情報の読み取り（判定・新規登録画面・設定画面。LGL-G03, G04, S15, S16）の `AuthFailure`**: 下の「判定の `AuthFailure`」と同じ理由で発生しない
- **新規登録の `NotFoundFailure`**: アカウントの作成・同意の送信で `NotFoundFailure` は発生しない（対象を探す処理が無い。送信の版数違いは `outdated` で返る）
- **同意の送信の時間切れ**: 送信は30秒で時間切れになり `NetworkFailure` として扱う（LGL-R21）。新規登録では失敗として先に進む（LGL-S11）
- **判定の `AuthFailure`**: `fetchLegalConfig` は誰でも読める場所の読み取り、`fetchConsents` はログイン情報が無効でも権限エラー（`permission-denied`）として返るため、接続できない以外の失敗はすべて `UnknownFailure` にまとめる（LGL-R09・R16・R27・R28）。判定で `AuthFailure` は発生しない
- **既定値の値が関数とアプリで同じであること・関数が `app_config/legal` を既定値で作ること**: 関数の中の動作と、アプリの定数の値の一致で、Cloud Functions 側のテストで検証する（概要 §既定値）
- **オンラインに戻ったことの検知**: 接続状態の監視（`ConnectivityMonitor.onStatusChanged`）は既存の仕組みで、この仕様書ではオンラインに戻ったときに判定することだけを定める（LGL-D50）
- **送信の `NotFoundFailure`**: 版数が違う場合は `Right(LegalAcceptResult.outdated)` で返し（LGL-R19）、エラーコード `not-found` は `UnknownFailure` にまとめる（LGL-R37）ため、送信で `NotFoundFailure` は発生しない
- **入力の境界・同じ値**: 文字の入力欄が無い。Firestore の値の境界は 5章（LGL-R05・R24・R29〜R35）で定める
- **対象の不在**: 同意の記録は追記・上書きで、変更・削除の対象が無いことは起きない（記録が無い場合は LGL-R11・R12・K04 で定める）
- **閲覧画面の WebView の中の操作**（ページ内のリンクの先の内容・拡大縮小・スクロール）: WEB のページの内容で、アプリの振る舞いではない。アプリが決める「戻る」の扱いは LGL-B21・B22 で定める
- **規約の本文の内容**（退会について必ず記載する事項を含む）: WEB 側で管理する。アプリは本文を持たない
- **改定するときの運用**（WEB とコンソールの更新手順）: 人の運用で、アプリの振る舞いではない。版数が変わったときの動作は LGL-D14・D34 で定める
- **版数の書式（`YYYY-MM-DD`）の検証**: 版数はコンソールで人が書き込む値で、アプリは文字列の一致だけを見る（LGL-K05・K06）
- **ログイン・新規登録そのものの動作**（メールアドレス・パスワードの入力チェック、アカウントの作成のエラー表示）: ログイン画面・新規登録画面の仕様の範囲。この仕様書では、新規登録画面の同意の欄と、登録の後の同意の送信、ログインが成功した後の判定だけを定める
- **退会処理の再開ダイアログ・他の端末での退会のダイアログの動作**: `docs/detailed_design/presentation/settings/settings_page.md`（ACD）の範囲。この仕様書では、それらが出ているときに同意ダイアログを出さないことだけを定める
- **設定画面の「このアプリについて」の項目の 4章の仕様**: 読み取りの結果で閲覧画面を開くかスナックバーを出すだけで、続けて持つ状態が無いため、4章の項目は作らない（読み取りの戻り値は 5章の `fetchLegalConfig` で定める）
- **同意ダイアログの「ログアウト」の失敗の種類**: `SignOutUseCase` の失敗は種類を区別せず「ログアウトできませんでした。もう一度お試しください。」にまとめる（`UnknownFailure`: LGL-A40、`NetworkFailure`: LGL-A52、`AuthFailure`: LGL-A53）。`NotFoundFailure` はログアウトでは発生しない（対象を探す処理が無い）。通信エラーダイアログでログアウトを促すと、ログアウトの失敗でログアウトさせることになり循環するため、原則-11 は当てはめない
- **閲覧画面・別のダイアログの上での表示**: 閲覧画面も「今の画面」として扱い、同意ダイアログやお知らせダイアログはその上に表示する（LGL-D44, D46）。下のダイアログ（フォルダの作成など）を他の端末での退会で閉じるかは ACD の範囲
- **「通信エラー」ダイアログ（`NetworkErrorDialog`）の外側タップ・戻る操作**: 全画面で共通のダイアログで、原則-11 の共通の扱いに従う。この仕様書では、表示されることと「OK」の後の動作だけを定める
- **端末の回転・横向き**: 縦向きでの表示（LGL-D20・D36）で、はみ出しが起きないことを確かめる。回転してもチェックの状態が保たれることは、画面の作り直しで State が消えない Riverpod の仕組みによるため、個別には定めない
- **他の端末での退会のダイアログを表示している間の判定**: 他の端末での退会の `phase` が `notifying`・`confirming`・`deleting`・`failed`（ダイアログを表示している間。お知らせダイアログの OK からログアウトが終わるまでの間も `notifying` のまま）の間は判定しない。`notifying` を LGL-V11、`confirming` を LGL-V62 で代表し、`deleting`・`failed` も同じ扱いとする。`checking`（退会済みかの確認中）の間は判定する（起動直後は両方の確認が同時に走るため。判定中に退会が分かった場合は LGL-D38・V35 のとおり結果を捨てる）
- **表示していない文書の改定**: 送信で関数が確かめるのは送った文書の版数だけで、表示していない文書が改定されていた場合は、次の判定のきっかけで同意ダイアログが出る（概要 §判定のタイミング）
